# 独立审判规则

当前规则 `1.0.0`：`packages/court-rules/config/v1.json`。

| 维度 | 评价对象 | 不自动构成过错 |
| --- | --- | --- |
| 行为合理性 | 明确约定、边界、要求、欺骗等具体行为 | 正常需求差异 |
| 事实与归因 | 无依据指责、动机推断、曲解、矛盾 | 表达受伤 |
| 沟通表达 | 人身攻击、侮辱贬低、嘲讽、攻击性表达 | 不够温柔 |
| 冲突处理 | 不合理升级、持续无依据指责、刺激、回避核心 | 正常暂停沟通 |

双方各维度独立 0–5，越高表示有依据的不当行为越严重，双方不共享分数。0不是“未知”；证据不足使用 `null`，并解释原因。

0：未发现足够过错依据。1：轻微、影响有限。2：比较明确、有一定影响。3：明显、实质影响。4：严重、较大影响。5：突出且有充分依据的严重问题。

## 总分与倾向（由程序处理）

仅在双方全部维度均可评分且关键事实充足时，产生完整总分，默认最高各20。任一维度不可评分或关键事实不足，不强制判断主要过错方。单方模式总分/责任结论保留为不足，局限单独展示。安全风险时完全暂停评分。

默认两方总分均不超过2 → “暂无明显过错”。否则差值不超过2 → “双方过错程度接近”。其余偏向总分更高的一方。阈值独立保存在 JSON；本规则仅为产品约定，不是科学测量。

关键事实不足时，Judge 将双方总分隐藏为 `null`，避免已知部分制造精确比较。重大过错通过 `seriousFaults` 独立提示，不能被加总掩盖。

## 证据引用与防重复

`case.*` 为案件描述，`A.*` / `B.*` 为具体陈述字段，`image:<uuid>` 为已上传截图，`context.participation` 为材料参与范围。真实模型必须提供具体 refs；后端拒绝不存在的来源。事实分为双方认可、材料支持、单方未核实、相互矛盾、无法确认。后端只能检查引用是否存在，无法机械验证模型对图片的解释是否忠实，仍需人工评估。

正分必须附具体行为标识与材料来源。同一方同一 `behaviorId` 不能跨维度重复；可区分后果必须分开说明。此校验不能完全识别换名后的语义重复，Prompt 与人工回归仍有必要。

## 修改方式

1. 新增规则 JSON，使用新的 version；保留旧文件，避免覆盖历史规则。
2. 修改维度数组、说明、maxScore、完整0至maxScore尺度和阈值。支持1–20个维度、每项最高1–20，页面与真实调用Schema根据配置生成。
3. 日常案件用 `COURT_RULES_VERSION` 选择规则；实验室从配置目录自动发现全部版本。
4. Prompt 在 `packages/judge/prompts/judge-v1.md` 单独编辑；同时更新 `PROMPT_VERSION`，以便历史比较。
5. 修改后运行单元/API测试，在实验室对相同虚构案例重跑、保存、比较，再做身份交换。Mock 参考分数是人工维护的V1样例，不替代新规则的真实模型检验。

每份判决保存完整规则快照、规则版本、Prompt版本、模型名称、提供商、是否Mock、原始结构化输出、耗时及可获得的用量/费用。
