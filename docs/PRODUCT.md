# V1 产品与流程

目的：分析一次具体争执，不给情侣或人格打长期评分，不宣称司法效力。

## 案件状态

`collecting → ready → judging → judged`

同设备：甲方立案 → 甲方提交并锁定 → 服务端授予独立乙方权限 → 乙方提交并锁定 → 材料公开 → 审理。

异地：甲方创建并获得邀请 → 乙方凭随机邀请在另一设备参与 → 双方独立提交（顺序不限）→ 材料公开 → 审理。乙方等待甲方时同样不能看到甲方未公开陈述。

单方：甲方创建 → 提交并锁定 → 可直接审理。明确缺少乙方材料，不能把单方叙事视为事实，不生成完整双人主要责任结论。

不要求认同对方说法或达成一致。原始陈述锁定，无补充举证、二审、上诉。全部正式材料在双方完成提交后对双方可见。截图不证明动机，不做真伪鉴定。

每方最多六张图片，标注左右角色、可调整顺序和预览。服务端验证归属、去重、人物标注及提交锁定。案件基本描述对参与者可见，尚未完成的个人陈述由角色隔离。

## 架构边界

- `apps/miniapp`：Taro 页面、动态评分组件和平台适配。图片选择、上传、鉴权下载、存储、邀请、导航封装在 `src/platform`，页面不直接调用 wx API。
- `apps/server`：Express 路由与配置；`Repository` 封装 SQLite 访问。替换数据库可保持业务/API契约。
- `packages/shared`：类型与 Zod Schema。
- `packages/court-rules`：规则 JSON、版本发现、规则验证及程序求和/比较。
- `packages/judge`：独立 Prompt、OpenAI 兼容多模态请求、引用与输出校验、Mock。
- `tests/cases`：全部人为虚构数据，无真实用户聊天。

安全风险优先于普通责任评分。模型识别到暴力、威胁、控制、骚扰等风险后，程序暂停评分，并提示现实危险联系当地警方或紧急服务，不认定犯罪。Mock 只有有限关键词提示，不能当安全检测器。

不包含支付、会员、排行榜、长期关系档案、多模型投票、多轮追问、二审、社区、公开判决、自动通知或发布功能。
